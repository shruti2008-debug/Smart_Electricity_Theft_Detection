# Shared Sensor Data Contract
**Project:** Smart Electricity Theft Detection  
**Version:** 1.0.0  
**Status:** Approved Standard

This document defines the canonical schema, database paths, physical units, and validation rules shared across all components:
- ESP32 Hardware Firmware (`firmware/`)
- Sensor Simulator (`simulator/`)
- Firebase Realtime Database (`firebase/`)
- AI / Machine Learning Engine (`ml/`)
- Firebase Cloud Functions (`functions/`)
- React Web Dashboard (`dashboard/`)

---

## 1. Firebase Realtime Database Hierarchy

```
/
├── system_test/
│   └── {uid}/                           <-- Ephemeral connection test ping/pong
│
├── devices/
│   └── {deviceId}/                      <-- Device registry and metadata
│       ├── deviceId: string
│       ├── name: string
│       ├── ownerUid: string
│       ├── status: "online" | "offline" | "warning"
│       ├── relayState: "CONNECTED" | "DISCONNECTED"
│       ├── lastSeen: timestamp (ms)
│       ├── location: string
│       ├── meterNumber: string
│       ├── isSimulator: boolean
│       └── registeredAt: timestamp (ms)
│
├── latest_readings/
│   └── {deviceId}/                      <-- Fast, real-time snapshot of the latest reading
│       └── [SensorReading Object]
│
├── readings/
│   └── {deviceId}/                      <-- Append-only historical log for ML and reporting
│       └── {readingKey}/
│           └── [SensorReading Object]
│
├── alerts/
│   └── {deviceId}/                      <-- Theft, tampering, and fault alert feed
│       └── {alertKey}/
│           ├── alertId: string
│           ├── deviceId: string
│           ├── timestamp: timestamp (ms)
│           ├── type: AlertType
│           ├── severity: "INFO" | "WARNING" | "CRITICAL"
│           ├── message: string
│           ├── anomaly_score: number (0.0 - 100.0)
│           ├── status: "ACTIVE" | "ACKNOWLEDGED" | "RESOLVED"
│           └── acknowledgedBy / resolvedBy: string
│
└── control/
    └── {deviceId}/                      <-- Remote actuator commands (Relay trip/reset)
        ├── relayCommand: "CONNECT" | "DISCONNECT"
        ├── requestedBy: string (uid)
        ├── requestedAt: timestamp (ms)
        ├── executed: boolean
        └── executedAt: timestamp (ms)
```

## 2. SensorReading Schema Specification

Every sensor reading pushed by the ESP32 firmware or the software simulator MUST adhere to this structure:

| Field Name | Type | Unit | Range / Constraints | Description |
|---|---|---|---|---|
| `deviceId` | `string` | — | Non-empty alphanumeric (e.g. `METER-001`, `SIM-001`) | Unique identifier of the meter or simulator |
| `timestamp` | `number` | Epoch ms | Positive integer (e.g. `1728638400000`) | UTC timestamp when the sample was recorded |
| `voltage` | `number` | Volts RMS | `0.0` to `300.0` V | AC voltage measured across line and neutral |
| `current` | `number` | Amperes RMS | `0.0` to `50.0` A | AC current measured via ACS712 sensor |
| `power` | `number` | Watts (W) | `0.0` to `15000.0` W | Active electrical power: $P = V \times I \times \text{PF}$ |
| `energy_kwh` | `number` (optional) | Kilowatt-hours (kWh) | $\ge 0.0$ | Cumulative energy consumed by load |
| `power_factor` | `number` (optional) | Ratio | `0.00` to `1.00` | Power factor (nominally $0.90 - 0.98$ for residential) |
| `frequency` | `number` (optional) | Hertz (Hz) | `45.0` to `55.0` Hz | Grid frequency (nominal 50.0 Hz) |
| `status` | `string` | Enum | `"NORMAL"`, `"SUSPICIOUS"`, `"TAMPERED"`, `"FAULT"` | Operating status determined by hardware/simulator |
| `anomaly_score` | `number` (optional) | Score | `0.0` to `100.0` | Output from ML anomaly detection engine |
| `risk_level` | `string` (optional) | Enum | `"LOW"`, `"MEDIUM"`, `"HIGH"` | Qualitative risk classification |
| `source` | `string` | Enum | `"esp32"` or `"simulator"` | Distinguishes physical hardware from simulated data |
| `modelVersion` | `string` (optional) | — | e.g. `"iso-forest-v1.0"` | Identifies the algorithm that generated the score |

### Example JSON Payload:
```json
{
  "deviceId": "SIM-001",
  "timestamp": 1728638400000,
  "voltage": 230.4,
  "current": 4.82,
  "power": 1054.2,
  "energy_kwh": 14.852,
  "power_factor": 0.95,
  "frequency": 50.02,
  "status": "NORMAL",
  "anomaly_score": 12.4,
  "risk_level": "LOW",
  "source": "simulator",
  "modelVersion": "iso-forest-v1.0"
}
```

## 3. Data Validation Rules

1. **Non-Negativity:** `voltage >= 0`, `current >= 0`, `power >= 0`, `energy_kwh >= 0`.
2. **Physical Consistency:** Power must satisfy:
   $$P \approx V \times I \times \text{PF} \pm 10\%$$
   If $V = 0$ or $I = 0$, then $P$ must be $0$.
3. **Simulated Flag:** Any data generated by the simulator MUST explicitly have `"source": "simulator"`. Real hardware MUST specify `"source": "esp32"`.
4. **Theft Anomaly Indicator:** An `anomaly_score` $> 65.0$ or a status of `"TAMPERED"` triggers a high-priority theft alert.
